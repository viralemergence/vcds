About

The Vector Competence Data Standards (VCDS) is maintained by Verena and aims to provide consistent terminology for describing vector competence experiments.

This data standard is extensible, that is you may include additional terms not in the standard. When validating data with the JSON schema, these terms will be ignored.

The growing threat of vector-borne diseases, highlighted by recent epidemics, has prompted increased focus on the fundamental biology of vector-virus interactions. To this end, experiments are often the most reliable way to measure vector competence (the potential for arthropod vectors to transmit certain pathogens). Data from these experiments are critical to understand outbreak risk.

Using the VCDS to describe vector competence studies facilitates interpretation and data sharing.

Schema

VCDS uses a JSON schema to describe the properties in a data set and the relationship between those properties. The JSON schema expects tabular data that contain at least the required fields.

Data can be validated against the JSON schema using a validation engine:

Terms

These are the properties of the JSON schema.

Each term card contains a plain language description and a link to a controlled vocabulary that provides a more technical description of the item.

The terms page has a search bar just below the table of contents. It can filter on any property of a term card (e.g. name, description, badge, etc.)

Templates

Excel templates are available to facilitate getting started with the VCDS. The columns in the excel spreadsheet correspond to the the properties in the JSON schema schema. To download a template, select the version you woule like to do use from the "download excel template" menu item.

Versioning

  1. All versions of VCDS will include a version number in their title (e.g. v1.0.0).
    Change type Examples Version bump
    Breaking Updating required fields, changing field names, adding or removing value restrictions 1.0.0 → 2.0.0 (major)
    Non-breaking, affects validation Refining regex patterns, correcting or refining enum values, modifying the directory structure 1.0.0 → 1.1.0 (minor)
    Non-breaking, no validation impact Updating descriptions, adding examples, modifying templates 1.0.0 → 1.0.1 (patch)
  2. When a new version of the schema is published, a new GitHub release must be created as well as a new version of the schema on Zenodo.
